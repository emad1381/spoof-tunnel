# Spoof Tunnel · EMAD

![Panel](docs/images/dashboard.png)
پنل مدیریت فارسی و هستهٔ مستقل تونل لایهٔ ۳ روی Linux. **TCP، UDP و ICMP** از رابط TUN عبور می‌کنند؛ ترافیک داخلی به UDP محدود نیست.

## نصب تک‌خطی

روی **هر دو VPS با کاربر root** اجرا کنید. بستهٔ آماده دانلود می‌شود؛ نیازی به Go، Node.js یا Rust روی سرور نیست.

```sh
curl -fsSL https://raw.githubusercontent.com/emad1381/spoof-tunnel/main/install.sh | bash
```

## امکانات

- ساخت تنظیمات مکمل دو طرف و خروجی JSON سمت مقابل.
- جداسازی IP واقعی، مبدأ جعلی و آدرس داخلی تونل.
- حامل ICMP، TCP خام، UDP، protocol 4 و protocol 253 با انتخاب مستقل رفت و برگشت.
- رمزنگاری AES-GCM، کلید مشترک تصادفی، کنترل replay و heartbeat احرازشده.
- تفکیک وضعیت پردازش از ارتباط طرف مقابل، شمارندهٔ ترافیک و لاگ زنده.
- SQLite و نصب systemd؛ بدون وابستگی Rust برای هستهٔ جدید.

## نصب

دو سرور Linux با TUN و قابلیت ارسال source spoof لازم است. برای ساخت، Go مطابق go.mod و Node.js 24 و npm نصب باشد:

```sh
bash scripts/build.sh
```

پوشهٔ کامل `dist` را به هر دو VPS منتقل کنید:

```sh
sudo bash dist/install.sh
```

نصب اول نام کاربری، رمز و URL را چاپ می‌کند؛ آن‌ها را نگه دارید. نصب دوباره دیتابیس را حفظ می‌کند. پنل HTTP است؛ برای مدیریت راه دور از HTTPS reverse proxy یا SSH forwarding استفاده کنید.

## ساخت اتصال

1. پنل هر دو سرور را باز کنید.
2. در یکی «ساخت اتصال دوطرفه» را بزنید.
3. IP واقعی ایران و خارج را وارد کنید؛ مقصد بسته‌ها همین آدرس‌های واقعی است.
4. مبدأ جعلی هر سمت را جدا وارد کنید؛ هر طرف باید مبدأ جعلی طرف مقابل را بداند.
5. حامل رفت و برگشت را انتخاب کنید؛ این گزینه نوع ترافیک داخلی را محدود نمی‌کند.
6. شبکهٔ داخلی `/30` انتخاب کنید. پیش‌فرض `10.77.0.0/30` است؛ برای اتصال بعدی شبکهٔ دیگری انتخاب کنید.
7. نقش همین پنل را مشخص و تنظیمات را بسازید.
8. JSON سمت مقابل را در صفحهٔ «اتصال‌ها» آن سرور وارد کنید. **فایل شامل PSK است؛ منتشرش نکنید.**
9. هر دو طرف را راه‌اندازی کنید. روشن‌شدن پردازش با تأیید ارتباط فرق دارد؛ پاسخ احرازشده جدا نمایش داده می‌شود.
10. از ایران `ping 10.77.0.2` بزنید و سرویس TCP/UDP را از IP داخلی خارج استفاده کنید.

TUN شبکهٔ خصوصی بین دو سرور ایجاد می‌کند؛ پورت عمومی را خودکار forward و مسیر پیش‌فرض را تغییر نمی‌دهد. سرویس باید روی IP داخلی مناسب گوش دهد یا forwarding مشخص تنظیم شود. [مثال عملیات](docs/OPERATIONS.md).

## عیب‌یابی

| وضعیت | اقدام |
|---|---|
| خطای پردازش | لاگ، مجوز TUN/raw socket، IP محلی و تداخل نام رابط را بررسی کنید. |
| پردازش روشن، بدون پاسخ | سمت دیگر، کلید، حامل‌های معکوس و پورت/شناسهٔ دریافت را تطبیق دهید. |
| هر دو روشن، بدون پاسخ | پذیرش spoof در هر دو دیتاسنتر، فایروال و rp_filter را بررسی کنید. |
| peer متصل، سرویس قطع | ابتدا ping داخلی؛ سپس bind، پورت سرویس و مسیر کاربردی را بررسی کنید. |
| اتصال نامنظم | ساعت دو سرور، MTU و افت بسته را بررسی کنید. |
| اتصال دوم اجرا نمی‌شود | نام رابط و subnet باید مستقل باشند. |

## محدودیت‌ها

این نسخه Linux و IPv4 است. TCP حامل، اتصال TCP عادی نیست. protocol 4 قالب اختصاصی دارد و با IPIP استاندارد کرنل سازگار نیست. پروژه با PenguTunnel سازگار نیست و ادعای ESP/AH/OSPF استاندارد ندارد. FEC، fallback خودکار و gateway تمام اینترنت پیاده نشده‌اند.

تست ایزولهٔ شش ترکیب حامل با ping، TCP، UDP و heartbeat موفق شد؛ تضمین همهٔ دیتاسنترها یا شبکه‌های واقعی نیست. [تست‌ها](docs/TESTING.md) و [معماری](docs/ARCHITECTURE.md).

سورس و سابقهٔ ParsaKSH با Apache-2.0 حفظ شده است. هستهٔ جدید از نو نوشته شده؛ باینری، تغییر لایسنس، کد دی‌کامپایل‌شده یا کلیدهای PenguTunnel در این مخزن نیست.
