*تصویر واقعی پنل v0.3.1 با بک‌اند Go و دیتابیس موقت SQLite است. سه تنظیم نمونه با آدرس‌های مخصوص مستندات ساخته شده‌اند و متوقف‌اند؛ تصویر ادعای اتصال یا سرعت VPS واقعی ندارد.*

## این پروژه چه کاری انجام می‌دهد؟

موتور `spoof-l3` بین دو سرور Linux یک رابط خصوصی و رمزنگاری‌شدهٔ TUN می‌سازد. برنامه‌ها از IP داخلی تونل استفاده می‌کنند؛ **TCP، UDP و ICMP داخلی** مستقل از نوع حامل بیرونی عبور می‌کنند. پنل تنظیمات، پردازش تونل، وضعیت ارتباط، فوروارد و لاگ‌ها را مدیریت می‌کند.

| هستهٔ شبکه | پنل مدیریت |
| --- | --- |
| حامل ICMP، UDP، TCP خام، پروتکل ۴ و پروتکل ۲۵۳ | رابط فارسی و راست‌به‌چپ با فونت محلی **وزیرمتن** |
| انتخاب مستقل حامل رفت و برگشت | ساخت تنظیمات مکمل و ورود/خروج JSON |
| AES-256-GCM، کلیدهای جهت‌دار و جلوگیری از replay | حالت روشن/تیره و منوی سازگار با موبایل |
| heartbeat با پاسخ احرازشده | نمایش جداگانهٔ اجرای پردازش و اتصال واقعی طرف مقابل |
| رابط و شبکهٔ مستقل برای هر اتصال | فوروارد TCP ورودی به سرویس سمت مقابل |
| فهرست مجاز متقابل برای گردش مبدأ جعلی | لاگ زنده، شمارنده‌های ترافیک و ذخیره‌سازی SQLite |

هستهٔ TUN و پنل باینری Go هستند؛ نصب Rust یا eBPF برای اجرای آن‌ها لازم نیست. مسیر UDP relay قدیمی به‌صورت جداگانه در سورس حفظ شده است.

## نصب و به‌روزرسانی

روی **هر سرور با کاربر root** اجرا کنید. معماری‌های Linux **amd64** و **arm64** پشتیبانی می‌شوند. پیش‌نیازها: systemd، iproute2، دسترسی به `/dev/net/tun`، و ابزارهای `curl`، `tar` و `sha256sum`.

```sh
curl -fsSL https://raw.githubusercontent.com/emad1381/spoof-tunnel/main/install.sh | bash
```

همین دستور برای آپدیت هم استفاده می‌شود: **آخرین Release منتشرشده** را متناسب با معماری دانلود می‌کند، checksumهای موجود را بررسی می‌کند، باینری‌ها را جایگزین و سرویس را راه‌اندازی مجدد می‌کند. صرف پوش‌کردن سورس، فایل نصب را به‌روز نمی‌کند؛ بسته‌های بیلدشده باید در Release منتشر شده باشند.

- نصب اول رمز مدیر و URL پنل را نمایش می‌دهد. رمز را نگه دارید؛ نسخهٔ قابل‌بازیابی آن ذخیره نمی‌شود.
- آپدیت، دیتابیس، رمز و تنظیمات موجود را حفظ می‌کند. پیش از ارتقا، سرویس را متوقف و از `/etc/spoof-panel` پشتیبان بگیرید.
- نسخه هنگام بیلد داخل پنل و موتور ثبت می‌شود؛ برچسب بالای پنل نسخهٔ باینری در حال اجراست.
- پنل HTTP ارائه می‌کند؛ برای مدیریت از راه دور، HTTPS reverse proxy یا SSH forwarding تنظیم کنید.

برای نصب مشخصاً نسخهٔ **v0.3.2**:

```sh
curl -fsSL https://raw.githubusercontent.com/emad1381/spoof-tunnel/v0.3.2/install.sh | SPOOF_RELEASE=v0.3.2 bash
```

خروجی انتشار شامل `spoof-tunnel-linux-amd64.tar.gz`، نسخهٔ `arm64` و فایل checksum آرشیوها یعنی `SHA256SUMS` است. روی VPS به Go، Node.js یا Rust نیاز ندارید.

## اتصال دو سرور

1. پنل هر دو سرور را باز کنید. در یکی وارد **ساخت اتصال** شوید.
2. **IP واقعی** و **مبدأ جعلی** هر سرور را جداگانه وارد کنید. مقصد بسته، IP واقعی است؛ مبدأ مورد انتظار، IP جعلی طرف مقابل است.
3. حامل رفت و برگشت، پورت دریافت یا شناسهٔ ICMP، و یک شبکهٔ داخلی آزاد `/30` را انتخاب کنید.
4. مشخص کنید این پنل روی ایران است یا خارج. سازنده هر دو تنظیم مکمل را تولید می‌کند و فقط سمت انتخاب‌شده را در همین پنل ذخیره می‌کند.
5. JSON سمت مقابل را دانلود و در صفحهٔ **اتصال‌ها** سرور دیگر وارد کنید. **این فایل کلید محرمانهٔ PSK دارد؛ منتشرش نکنید.**
6. هر دو سمت را اجرا کنید. روشن‌شدن پردازش به‌تنهایی اثبات اتصال نیست؛ منتظر پاسخ احرازشدهٔ طرف مقابل بمانید.
7. ابتدا ارتباط داخلی را آزمایش کنید، سپس سرویس موردنظر را:

```sh
# روی ایران، برای شبکهٔ اول مثال
ping -c 3 10.77.0.2
```

سرویس سمت خارج باید روی IP داخلی تونل یا آدرس wildcard مناسب گوش دهد. این تنظیم، مسیر پیش‌فرض را عوض نمی‌کند و خودکار دروازهٔ تمام اینترنت نمی‌سازد.

## یک ایران و چند سرور خارج

برای **هر سرور خارج یک جفت تنظیم جدا** بسازید. هر جفت کلید و رابط مستقل دارد؛ شبکه‌ها باید بدون هم‌پوشانی باشند. پیشنهاد خودکار شبکه بر اساس تنظیمات ذخیره‌شده در همان پنل انجام می‌شود و بک‌اند تداخل ثبت‌شدهٔ شبکه یا نام رابط را رد می‌کند.

| اتصال | شبکهٔ خصوصی | IP داخلی ایران | IP داخلی خارج | پورت/شناسهٔ پیشنهادی دریافت ایران |
| --- | --- | --- | --- | --- |
| ایران ↔ خارج A | `10.77.0.0/30` | `10.77.0.1` | `10.77.0.2` | `5001` |
| ایران ↔ خارج B | `10.77.0.4/30` | `10.77.0.5` | `10.77.0.6` | `5002` |
| ایران ↔ خارج C | `10.77.0.8/30` | `10.77.0.9` | `10.77.0.10` | `5003` |

**پورت دریافت خودکار افزایش پیدا نمی‌کند.** برای خوانایی تنظیمات و کاهش پردازش متقاطع، مقدار مجزا انتخاب کنید. پورت حامل مشترک با کلید مستقل هم پشتیبانی می‌شود؛ آزمون یک ایران و سه خارج حتی مبدأ جعلی مشترک را بررسی می‌کند. یک کلید یا تنظیم یکسان را برای اتصال‌های متفاوت کپی نکنید. بررسی پنل محدود به تنظیمات ثبت‌شدهٔ خودش است؛ محدودهٔ شبکه‌های LAN/VPN و مسیرهای موجود سیستم را نیز در نظر بگیرید.

### کدام پورت برای چه کاری است؟

| گزینه | کاربرد |
| --- | --- |
| پورت دریافت حامل | پورت مقصد UDP یا TCP خام در بستهٔ بیرونی؛ تنظیم ارسال طرف مقابل باید با آن هماهنگ باشد |
| شناسهٔ ICMP | شناسهٔ عددی حامل؛ پورت سرویس TCP نیست |
| پروتکل ۴ و ۲۵۳ | پورت TCP/UDP ندارند؛ فریم رمزشده مستقیم داخل پروتکل IP قرار می‌گیرد |
| پورت ورودی فوروارد | درگاه TCP سرور ورودی که کاربران به آن متصل می‌شوند |
| پورت سرویس مقصد | سرویس روی IP داخلی سرور خارج انتخاب‌شده |
| پورت پنل | فقط مدیریت؛ مستقل از پورت تونل و سرویس کاربران |

مثلاً روی ایران، `2443 → 10.77.0.2:443`، `3443 → 10.77.0.6:443` و `4443 → 10.77.0.10:443` سه سرور خارج را پوشش می‌دهند. پورت سرویس `443` روی IPهای مقصد متفاوت قابل‌تکرار است؛ اما پورت ورودی قوانین فعال روی یک سرور ایران باید یکتا باشد.

قانون را در ویرایش همان اتصال، تب **فوروارد معکوس** بسازید. قانون همراه تونل شروع و متوقف می‌شود. شنونده روی `0.0.0.0` باز می‌شود؛ فایروال را متناسب با کاربران مجاز تنظیم کنید. فوروارد ورودی فعلاً **فقط TCP** است؛ UDP داخلی همچنان از خود TUN عبور می‌کند.

## عیب‌یابی

| نشانه | بررسی اولیه |
| --- | --- |
| پردازش اجرا نمی‌شود | لاگ اتصال، IP محلی، مجوز TUN/raw socket و تداخل رابط |
| پردازش روشن است، طرف مقابل پاسخ ندارد | اجرای سمت دیگر، تطابق کلید، IPهای واقعی/جعلی، حامل‌ها و پورت/شناسه‌های مکمل |
| هر دو روشن‌اند ولی پاسخی نیست | پذیرش spoof در دیتاسنترها، فایروال و reverse-path filtering |
| ارتباط احرازشده است، سرویس کار نمی‌کند | ping داخلی، آدرس bind، پورت سرویس و قانون فوروارد |
| اتصال دوم مشکل دارد | نام رابط مستقل، شبکهٔ غیرهم‌پوشان و واردکردن فایل درست طرف مقابل |

```sh
systemctl status spoof-panel
journalctl -u spoof-panel -n 100 --no-pager
/opt/spoof-panel/spoof-panel --version
/etc/spoof-panel/spoof-l3 --version
```

اگر رمز مدیر را فراموش کردید، روی سرور بازنشانی کنید. رمز باید ۱۲ تا ۷۲ بایت UTF-8 باشد؛ این کار توکن‌های ورود قبلی را باطل می‌کند:

```sh
/opt/spoof-panel/spoof-panel --setup --setup-pass 'YOUR_NEW_PASSWORD'
```

برای گردش چند مبدأ جعلی، **همان فهرست را در مبدأهای مجاز طرف مقابل** نیز وارد کنید. ذخیره در یک پنل، سرور جداگانهٔ طرف مقابل را خودکار تغییر نمی‌دهد.

## ساخت و آزمون

برای بیلد از Linux/WSL، نسخهٔ Go مشخص‌شده در [go.mod](go.mod)، Node.js 24 و npm استفاده کنید:

```sh
SPOOF_VERSION=v0.3.2 bash scripts/build.sh
sudo bash dist/install.sh
```

بیلد، رابط را به فایل‌های نهایی تبدیل و داخل `spoof-panel` قرار می‌دهد؛ موتور `spoof-l3` را می‌سازد و هر دو را همراه نصب‌کننده و مستندات بسته‌بندی می‌کند. GitHub Actions پیش از تولید بسته‌های هر دو معماری، اعتبارسنجی را اجرا می‌کند.

آزمون‌ها شامل **۲۵ ترکیب مرتب رفت/برگشت حامل**، **پنج حالت گردش مبدأ**، heartbeat با RTT بالاتر از سه ثانیه و **یک ایران و سه خارج هم‌زمان روی هر پنج حامل** با انتقال هم‌زمان TCP/UDP و توقف/راه‌اندازی مستقل هستند. **۱۴ سناریوی مرورگر** رفتار پنل و فونت محلی فارسی را بررسی می‌کنند؛ race testهای Go و آزمون HTTP/SQLite واقعی بک‌اند را پوشش می‌دهند. جزئیات در [راهنمای آزمون](docs/TESTING.md)، [معماری](docs/ARCHITECTURE.md)، [عملیات](docs/OPERATIONS.md) و [گزارش اصلاحات](docs/FIXES-2026-11-01.md) آمده است.

## محدوده و مجوز

این موتور Linux و IPv4 است. fallback خودکار حامل، FEC، ارسال مجدد/کنترل ازدحام اختصاصی، IPv6 و راه‌انداز دروازهٔ تمام اینترنت ندارد. TCP خام هندشیک TCP معمولی انجام نمی‌دهد. پروتکل ۴ با IPIP استاندارد کرنل سازگار نیست و پشتیبانی GRE، OSPF یا IPsec استاندارد ادعا نمی‌شود.

موفقیت در namespaceهای ایزوله، تضمین پذیرش spoof در دیتاسنتر، عبور از فیلترینگ یا سرعت پایدار تولیدی نیست. جفت VPS واقعی را جداگانه آزمایش کنید. ARM64 cross-compile می‌شود؛ آزمون روی سخت‌افزار ARM64 و نصب systemd روی VPS واقعی، بررسی‌های جداگانهٔ استقرارند. طراحی رمزنگاری ممیزی مستقل نشده است.
