# اصلاحات و اعتبارسنجی نسخهٔ v0.3.1-dev

مبنای تغییرات: شاخهٔ main در کامیت `7983591aacec4ec2d31b1b3f18cbeddd6aa0de6e`. این نسخهٔ اصلاحی روی دسکتاپ آماده شده است؛ وضعیت اجرای GitHub Actions یا نصب روی VPS واقعی را به‌عنوان نتیجهٔ تست محلی گزارش نمی‌کند.

## اصلاحات اصلی

- چرخهٔ فوروارد TCP بازنویسی شد: listener پیش از شروع worker ثبت می‌شود، شروع/توقف سریال است، dial با لغو متوقف می‌شود و همهٔ workerها پیش از restart جمع می‌شوند.
- EOF فقط همان جهت TCP را half-close می‌کند؛ پاسخ جهت مقابل قطع نمی‌شود. ناظر دائمی برای اتصال تمام‌شده باقی نمی‌ماند.
- مرگ سریع پردازش تونل نمی‌تواند ورودی فوروارد را باز باقی بگذارد. خطاهای شروع، از جمله اعتبارسنجی و فایل اجرایی، در وضعیت پنل ذخیره و نمایش داده می‌شوند.
- فهرست صریح مبدأهای مجاز طرف مقابل برای گردش چند IP اضافه شد؛ کانفیگ‌های تک‌آدرسی قبلی همچنان معتبرند. لیست هر سمت باید با peer هماهنگ شود.
- challengeهای heartbeat تا ۱۵ ثانیه نگه‌داری می‌شوند؛ پاسخ معتبر دیررس با probe بعدی باطل نمی‌شود و پاسخ تکراری پذیرفته نمی‌شود.
- توقف تستر منتظر پایان اجرای قبلی می‌ماند. حلقهٔ بازه‌های IPv4 در انتهای فضای آدرس سرریز نمی‌کند. پارامترهای CLI/API تستر اعتبارسنجی مشترک دارند.
- پیش‌نمایش زندهٔ تستر به ۲۰۰ ردیف محدود شده است؛ شمارنده‌ها، کپی و دانلود کامل باقی می‌مانند. ترتیب ردیف‌های زنده پایدار است.
- قوانین غیرفعال فوروارد غیرفعال ذخیره می‌شوند. پورت پنل و حامل TCP محلی از ورودی فوروارد محافظت می‌شوند.
- شبکه‌های TUN هم‌پوشان، نام رابط تکراری و شبکه‌ای که مقصد واقعی اتصال دیگری را در بر می‌گیرد در سرور رد می‌شوند. آدرس شبکه و broadcast برای میزبان TUN پذیرفته نمی‌شوند.
- ذخیرهٔ تنظیمات قدیمی HTTP 409 می‌گیرد. ذخیرهٔ استخر IP نسخهٔ جدید را به frontend برمی‌گرداند و فرم عمومی آن را بازنویسی نمی‌کند.
- اطلاعات کارت اتصال دوباره نمایش داده می‌شوند. منوی موبایل دکمهٔ بستن، Escape و مدیریت focus دارد. پنجرهٔ حذف نیز focus را نگه می‌دارد و با Escape بسته می‌شود.
- خطای ورود فرم را reload نمی‌کند. تستر وضعیت فعال سرور را هنگام ورود به صفحه بازیابی می‌کند. پاسخ قدیمی polling نمی‌تواند وضعیت جدیدتر را جایگزین کند؛ درخواست‌های دوره‌ای هم‌پوشان نمی‌شوند. درخواست‌های JSON مهلت ۱۵ثانیه‌ای دارند و سرور خواندن/نوشتن HTTP را زمان‌بندی می‌کند.
- تم روشن بدون hydration mismatch کار می‌کند و انتخاب تم حفظ می‌شود. حرکت‌های غیرضروری با prefers-reduced-motion حذف می‌شوند.
- «ترافیک کل» مجموع اتصال‌هاست و مفهوم حذف محلی با افت مسیر اشتباه گرفته نمی‌شود. نام‌های فارسی براساس تعداد نویسه اعتبارسنجی می‌شوند؛ رمز عبور براساس بایت UTF-8.
- رمز مدیر به شکل قابل‌بازیابی در SQLite یا credentials.txt ذخیره نمی‌شود. مهاجرت نسخهٔ قبلی را حذف می‌کند؛ backupهای قدیمی ممکن است آن را داشته باشند. نصب مجدد رمز فعلی را عوض نمی‌کند؛ reset صریح CLI و HTTP هر دو JWTهای قبلی را باطل می‌کنند.
- JWT لاگ WebSocket در URL قرار نمی‌گیرد؛ از هدر subprotocol استفاده می‌شود.
- در مسیر قدیمی Rust/CGo، دریافت‌کننده پیش از آزادشدن handle پایان می‌یابد، ارسال با Close هم‌زمان از handle آزادشده استفاده نمی‌کند و بستن UDP با ارسال روی کانال بسته برخورد نمی‌کند. تغییر سراسری sysctl مربوط به ICMP حذف شده است.
- build خطاهای TypeScript و Lint را نادیده نمی‌گیرد. workflowها برای تست و بسته‌بندی موتور جدید هماهنگ‌اند. بسته‌های amd64 و arm64 دارای checksum و نصب‌کنندهٔ LF هستند؛ نصب‌کننده پیش از جایگزینی، قابلیت اجرای باینری را بررسی می‌کند و شکست سرویس را موفقیت گزارش نمی‌کند.

## موارد عملیاتی

برای گردش چند IP، فهرست هر سمت را در «فهرست مبدأهای مجاز طرف مقابل» سمت دیگر وارد کنید. پورت عمومی فوروارد فقط با ساخت قانون صریح باز می‌شود؛ سرویس مقصد باید روی IP داخلی طرف مقابل گوش دهد. UDP داخلی از TUN عبور می‌کند؛ فوروارد ورودی این نسخه TCP است.

رمز نصب اول یک‌بار نمایش داده می‌شود. برای بازنشانی، روی سرور از `spoof-panel --setup --setup-pass NEW_PASSWORD` استفاده کنید. فایل credentials.txt فقط اطلاعات اتصال را نگه می‌دارد.

آزمون‌های موفق، تضمین پذیرش spoof در دیتاسنتر، عبور از فیلترینگ، سرعت پایدار، همهٔ مرورگرها یا ثبات نامحدود نیستند. XDP اختیاری قدیمی و IPv6 بخشی از موتور TUN تولیدی نیستند. ارزیابی نهایی استقرار باید روی جفت VPS مقصد انجام شود.

## تأیید نهایی با پنل واقعی — ۲۰۲۶-۱۱-۰۲

مرورگر Edge به باینری نهایی Linux با SQLite موقت متصل شد؛ در این مرحله API شبیه‌سازی نشد. ورود، ساخت جفت اتصال، ذخیرهٔ استخر IP و سپس فرم عمومی، reload و حفظ داده، ثبت فوروارد، اتصال WebSocket احرازشده بدون JWT در URL، تغییر رمز و بازگشت به داشبورد همگی موفق بودند. هیچ pageerror ثبت نشد. سرور QA و دیتابیس موقت پس از آزمون جمع‌آوری شدند. در این آزمون هیچ تونل عمومی یا اتصال به VPS واقعی ایجاد نشد.

## آزمون چند اتصال هم‌زمان — ۲۰۲۶-۱۱-۰۲

در namespaceهای خصوصی Linux، پنل و موتور واقعی با یک IP ایران و سه سرور خارج هم‌زمان اجرا شدند. در هر پنج حامل ICMP، UDP، TCP، IPIP و پروتکل ۲۵۳، پورت/شناسهٔ حامل و مبدأ جعلی سرورهای خارج مشترک بودند، اما کلیدها، شبکه‌های TUN و پورت‌های ورودی فوروارد مستقل بودند. انتقال TCP مستقیم و از طریق فوروارد، UDP داخلی، پاسخ متمایز هر سرویس، رد شبکهٔ هم‌پوشان و پورت ورودی تکراری، و ادامهٔ کار اتصال دوم هنگام توقف/راه‌اندازی اتصال اول همگی موفق بودند. فایل `scripts/integration_multipeer.py` این سناریو را در CI تکرار می‌کند.

فونت وزیرمتن به‌صورت self-hosted همراه خروجی پنل ارائه می‌شود. آزمون مرورگر بارگذاری واقعی فونت فارسی، RTL، وراثت فونت در متن، ورودی‌ها و دکمه‌ها و نبود درخواست به سرویس فونت گوگل را تأیید کرد. مجموع سناریوهای Playwright اکنون ۱۳ است.
